# SE Import — Swimmer Matching Scenarios (as built in v2.11)

**Purpose.** The SE PB Report Import has to decide, for every swimmer in the SE report, which dashboard
swimmer (if any) they are. There are three outcomes, and they behave very differently:

| Outcome | What the coach sees | What happens |
|---|---|---|
| **Auto-matched** | Counted under "auto-matched"; listed (informational) in the "N swimmer(s) auto-matched" box, with a gold note if the SE report's name differs | Applied with **no tick needed** |
| **Suggested match** | Listed under "Suggested matches - confirm each one" with a checkbox and a reason | Applied **only if the coach ticks it** (unticked = nothing happens) |
| **Skipped** (unmatched / ambiguous) | Listed in the "N swimmer(s) in the report will be skipped" box with a reason | **Never applied**; no swimmer is ever created |

This document records exactly what the code does today, so v2.12 can revisit the **Suggested matches**
rules deliberately. The table below is generated by `node test_se_matching_matrix.js --table`, which
extracts the real matcher out of `index.html` and pins each scenario's result, so this document cannot
silently drift from the code (change a rule and a row fails, on purpose).

---

## 1. How the matcher decides (in this order)

Inputs per SE swimmer: SE # (optional), surname, forename, date of birth, gender (`Boys`/`Girls`).
Names are compared after `normaliseNameKey()` (Unicode NFKC, lower-case, whitespace collapsed).

1. **SE # tier** (only if the SE report line has an SE #). Look for dashboard swimmers holding that SE #.
   - More than one holds it -> **Skipped (ambiguous)**.
   - Exactly one, and its date of birth **and** gender match -> **Auto-matched** (the name is not compared; a difference is only flagged).
   - Exactly one, but date of birth or gender differs -> **Suggested (needs review)**. The reason names both values (roster and SE report) and says when the day and month look swapped (v2.12).
   - None -> go to tier 2.
2. **Name + date of birth tier.** Look for dashboard swimmers with the identical (normalised) full name **and** the same date of birth.
   - More than one -> **Skipped (ambiguous)**.
   - Exactly one, but the dashboard holds a *different* SE #, or gender differs -> **Suggested (needs review)**.
   - Exactly one and nothing conflicts -> **Auto-matched**.
   - None -> go to tier 3.
3. **Surname + date of birth + gender tier (never auto-applied).** Candidates share date of birth and gender, and the dashboard name *ends with* the SE surname.
   - Candidates with **no** SE # on the dashboard are preferred over ones that already hold a different SE # (the "twin with their own number" case). If every candidate holds a different SE #, they are still offered, with the conflict named in the reason (a prior version dropped them to "unmatched", which was a bug).
   - If any candidate's first name is "similar" (first word equal, or one is a prefix of the other with at least 2 letters: Arty/Artyom, Mary/Mary Jane) only those are considered, and the result is **Suggested (likely)**; otherwise **Suggested (needs review)**.
   - More than one candidate left -> **Skipped (ambiguous)**. None -> **Skipped (unmatched)**.
4. **Cross-check across the whole report.** If two SE swimmers resolve to the *same* dashboard swimmer, both become **Skipped (ambiguous)**, so two reports can never write into one child's record.

Hidden and Former Swimmers are matched like anyone else. The SE report's date of birth is never written to the dashboard.

## 3. What ticking a suggested match does

- Imports the PB times from the SE report into that dashboard swimmer's record (new results, conflicts and probable duplicates are then handled exactly as for an auto-match).
- **Never** changes the swimmer's name, date of birth, gender, squad or hidden state.
- **Does** fill in the SE # from the SE report **if the dashboard swimmer has none** (a blank is filled; an existing SE # is never overwritten). The in-app text now says so (known-bugs #12, fixed in v2.12).
- Unticked = skipped; nothing is written.

## 4. Observations to revisit in v2.12

These are facts about current behaviour, not decisions. Items marked **(decision)** need the coach's view.

1. **SE # outranks the name (A).** A swimmer whose SE # matches is auto-matched even if the first name differs. This is deliberate (it is how Arty/Artyom works once the SE # is on the dashboard), but it means a name difference is only visible in the "auto-matched" box. **(decision)** keep, or surface name differences more prominently / let the coach exclude an auto-match?
2. **The most common "suggested" case is C: SE # and name match but the date of birth differs.** Ticking it imports PBs into a swimmer whose date of birth the report disagrees with. The review does not currently show both dates of birth side by side, and the app never corrects a date of birth. **(decision)** show both dates; require a stronger confirmation; or offer to correct the dashboard date of birth (Sheet-authoritative field, so it would need care)?
3. **A date-of-birth typo with no SE # link is "unmatched" (K, L)** even when the name is identical. Date of birth is the safety anchor for minors, so this was deliberate, but a coach may expect a suggestion. **(decision)**
4. **Gender mismatches are inconsistent.** Exact name + date of birth with a different gender is Suggested (H); a *similar* name with a different gender is Skipped (M).
5. **First-name similarity is prefix-only.** Mike/Michael, Liz/Elizabeth and Bob/Robert are "needs review", not "likely"; an accent difference (T) is "needs review" too. Folding diacritics (NFKD) would turn T into an exact match; a small nickname table would help the rest. **(decision)** how far to go.
6. **Surname handling is strict.** The dashboard name must *end with* the SE surname exactly: a hyphen/space difference (R) or reversed order (S) is Skipped.
7. **Two plausible candidates are Skipped (Q), not shown for the coach to choose between.** A "pick one" control would be a UI change.
8. **There is no "exclude this one" on an auto-match.** The only way to stop an auto-match applying is to cancel the import.
9. **Dashboard-side SE # collisions (N)** are Skipped; there is no tool to find/fix duplicate SE #s.
10. **Name keys differ between features.** The SE import normalises names (NFKC/lower/collapse whitespace); the Google Sheets sync matches on lower-case + trim only (`swimmerSyncKey`). Known-bugs #10.

## 4b. Status after v2.12

Changed in v2.12 (all pinned by `test_se_matching_matrix.js` and `probe_stage2.js`):
- **Item 2 (DOB mismatch):** the suggestion's reason now shows both dates of birth and flags a day/month swap; the import summary lists swimmers whose date of birth differs from the SE report. The dashboard's date of birth is still never changed.
- **Item 5 (accents):** accents are folded when judging whether two first names look alike (Artyóm / Artyom is now "likely"); it is a suggestion only and never makes a name auto-match, because `normaliseNameKey` is deliberately unchanged.
- **Item 10 (name keys):** the Google Sheets sync now uses the same `normaliseNameKey`; two swimmers that collapse to one key stop a sync (or an upload-merge) before anything is changed.
- **Wording (#12):** fixed.
Not changed (no demand yet): hyphenated surnames (R), reversed name order (S), "pick one" for two candidates (Q), excluding a single auto-match, the column C gender flag.
